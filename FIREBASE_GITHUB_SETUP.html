Tripwise Firebase-first setup

This guide uses GitHub's website and Firebase's website. You do not need Git commands, GitHub Desktop or a local terminal for the deployment workflow.

The app in this package is designed to use:

  • Firebase Authentication for accounts.
  • Cloud Firestore for trips and expenses.
  • Firebase Hosting for the live website.
  • GitHub Actions, configured from the GitHub website, to publish updates automatically.

The app does not use localStorage for trip data. The service worker only caches the application files so the page can load; it does not cache trips, expenses or passwords.

Before you start

You need:

  1. A GitHub account.
  2. A Google account for Firebase.
  3. The extracted Tripwise ZIP folder.
  4. A browser. No Git installation is required for the steps below.

Part 1 — Create the GitHub repository in the browser

1. Open GitHub

Open github.com and sign in.

2. Create an empty repository

  1. Click the plus button in the top-right corner.
  2. Click New repository.
  3. Enter tripwise as the repository name.
  4. Choose Private while developing, or Public if you want the source code visible.
  5. Leave Add a README file unchecked.
  6. Leave Add .gitignore unchecked.
  7. Leave Choose a license unchanged.
  8. Click Create repository.

The repository name is not your website domain. It is only the name of the code storage area on GitHub.

3. Upload the app files

  1. On the empty repository page, click uploading an existing file.
  2. Open the extracted tripwise folder on your computer.
  3. Select and upload these files:
index.html
firebase-config.js
firebase.json
firestore.rules
manifest.webmanifest
sw.js
icon.svg
README.html
FIREBASE_GITHUB_SETUP.html
  1. Enter the commit message Add Firebase Tripwise app.
  2. Select Commit directly to the main branch.
  3. Click Commit changes.

Do not upload a Firebase Admin service-account JSON file. It is never needed in the repository.

Part 2 — Create the Firebase project

1. Create the project

  1. Open Firebase Console.
  2. Click Add project.
  3. Use a name such as tripwise-production.
  4. Analytics is optional; you can turn it off.
  5. Click Create project.
  6. Click Continue when the project is ready.

The Firebase project ID becomes part of the free hosting address, such as tripwise-production.web.app. Firebase project IDs must be globally unique.

2. Register a Web app

  1. In Firebase Console, open Project settings using the gear icon.
  2. Scroll to Your apps.
  3. Click the Web icon </>.
  4. Give the app a nickname such as Tripwise web.
  5. Do not enable Firebase Hosting from this registration screen yet.
  6. Click Register app.
  7. Firebase will display a firebaseConfig object.

You will see values similar to:

const firebaseConfig = {
  apiKey: "...",
  authDomain: "tripwise-production.firebaseapp.com",
  projectId: "tripwise-production",
  storageBucket: "tripwise-production.firebasestorage.app",
  messagingSenderId: "...",
  appId: "..."
};

3. Add the Web config through GitHub's website

  1. Open your GitHub tripwise repository.
  2. Click firebase-config.js.
  3. Click the pencil Edit this file button.
  4. Replace the placeholder values with the values from Firebase Console.
  5. Keep the structure like this:
window.TRIPWISE_FIREBASE_CONFIG = {
  apiKey: "PASTE_YOUR_API_KEY",
  authDomain: "YOUR_PROJECT_ID.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  storageBucket: "YOUR_PROJECT_ID.firebasestorage.app",
  messagingSenderId: "PASTE_YOUR_SENDER_ID",
  appId: "PASTE_YOUR_APP_ID"
};
  1. Scroll down and click Commit changes.

The Firebase Web config is intended to be included in a browser app. It is not an Admin SDK secret. Security comes from Authentication and Firestore Rules. Never put an Admin SDK private key in this file.

Part 3 — Enable user accounts

1. Enable email and password login

  1. In Firebase Console open Build → Authentication.
  2. Click Get started.
  3. Open the Sign-in method tab.
  4. Select Email/Password.
  5. Turn on the first Email/Password switch.
  6. Click Save.

The app now shows a sign-in screen. Users can click Create a new account from the app.

2. Add users yourself, if required

You can also create accounts manually:

  1. Open Authentication → Users.
  2. Click Add user.
  3. Enter the user's email address.
  4. Set a temporary password.
  5. Click Add user.

Firebase automatically generates a secure UID for every user. The app uses the UID to store that user's workspace at:

users/{uid}/workspaces/main

Do not store user passwords in GitHub, Firestore, the app code or browser storage.

Part 4 — Create the Firestore database

  1. In Firebase Console open Build → Firestore Database.
  2. Click Create database.
  3. Choose Production mode.
  4. Select a region close to your users. For India, choose the closest available Asia region.
  5. Click Create.

Publish the correct Firestore Rules in the browser

  1. Open Firestore Rules.
  2. Replace the rules with the following:
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/workspaces/{workspaceId} {
      allow read, write: if request.auth != null
        && request.auth.uid == userId;
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}
  1. Click Publish.

These rules mean a signed-in user can read and write only their own workspace. No anonymous visitor can read or modify trips.

Part 5 — Turn on Firebase Hosting

  1. In Firebase Console open Build → Hosting.
  2. Click Get started.
  3. Continue through the introduction.
  4. Leave the Hosting site with its default name.
  5. Do not delete or change the Firestore rules.

Firebase will provide a free address based on the project ID:

https://YOUR_PROJECT_ID.web.app

The website is not live until GitHub Actions performs the first deployment.

Part 6 — Deploy from GitHub without Git commands

This uses GitHub Actions from the GitHub website.

1. Create a Firebase deployment key

  1. In Firebase Console open Project settings.
  2. Open the Service accounts tab.
  3. Click Generate new private key.
  4. Confirm and download the JSON file.
  5. Keep the JSON file private. Do not upload it as a normal repository file.

2. Add the key as a GitHub Secret

  1. Open your GitHub tripwise repository.
  2. Click Settings.
  3. In the left menu open Secrets and variables → Actions.
  4. Click New repository secret.
  5. Set the name to:
FIREBASE_SERVICE_ACCOUNT
  1. Open the downloaded JSON file in a text editor.
  2. Copy the entire JSON contents.
  3. Paste it into the Secret value field.
  4. Click Add secret.
  5. Delete the downloaded JSON file from your computer after confirming the secret was saved, or store it only in a password manager.

3. Create the GitHub Actions workflow in the browser

  1. Return to the repository's main page.
  2. Click Add file → Create new file.
  3. For the filename, enter exactly:
.github/workflows/firebase-hosting.yml
  1. Paste this workflow, replacing YOUR_PROJECT_ID with your Firebase project ID:
name: Deploy Tripwise to Firebase Hosting

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Download repository
        uses: actions/checkout@v4

      - name: Deploy to Firebase Hosting
        uses: FirebaseExtended/action-hosting-deploy@v0
        with:
          repoToken: ${{ secrets.GITHUB_TOKEN }}
          firebaseServiceAccount: ${{ secrets.FIREBASE_SERVICE_ACCOUNT }}
          projectId: YOUR_PROJECT_ID
          channelId: live
  1. Click Commit changes.

GitHub will start the workflow automatically. Open the repository's Actions tab to watch it.

When the workflow finishes with a green check mark, open:

https://YOUR_PROJECT_ID.web.app

Part 7 — First login and first cloud save

  1. Open the Firebase Hosting URL.
  2. Click Create a new account.
  3. Enter your name, email and password.
  4. Click Create account.
  5. The app creates a new Firestore workspace for that Firebase user.
  6. Add or edit a trip.
  7. Add an expense.
  8. Refresh the page.
  9. Sign out and sign back in.
  10. Confirm the same trips and expenses appear.

If you can see the same data after signing in again, Firestore sync is working.

Part 8 — Add a custom domain

GitHub does not create the website domain in this setup. GitHub stores the files and runs the deployment workflow. Firebase Hosting provides the website domain.

Option A: Use the free Firebase domain

Use the address Firebase gives you:

https://YOUR_PROJECT_ID.web.app

This requires no domain purchase.

Option B: Connect your own domain

You need to buy a domain from a domain registrar such as Cloudflare Registrar, Namecheap, GoDaddy or another provider.

  1. In Firebase Console open Hosting.
  2. Click Add custom domain.
  3. Enter your domain, for example:
travel.yourdomain.com
  1. Firebase will display a verification TXT record.
  2. Open your domain registrar's DNS settings.
  3. Add the TXT record exactly as Firebase shows it.
  4. Return to Firebase and click Verify.
  5. Firebase will show A records or CNAME records.
  6. Add those records in your domain registrar's DNS settings.
  7. Wait for DNS to update. This can take a few minutes or, sometimes, up to 24 hours.
  8. Firebase automatically provisions HTTPS/SSL after verification.

For the root domain yourdomain.com, follow Firebase's exact DNS instructions. Do not guess the A-record values.

Add the custom domain to Authentication

After the custom domain works:

  1. Open Firebase Console Authentication.
  2. Open Settings.
  3. Find Authorized domains.
  4. Click Add domain.
  5. Add your custom domain, for example:
travel.yourdomain.com

This allows sign-in and password reset to work on the custom domain.

Part 9 — Test the finished app

Test all of these before sharing the link:

  • Create a new account.
  • Sign out and sign back in.
  • Create a trip.
  • Edit a trip.
  • Add an expense.
  • Refresh the page.
  • Open the website on a second device.
  • Sign in with the same account.
  • Confirm the data is present.
  • Create a second Firebase account.
  • Confirm the second account does not see the first account's private workspace.
  • Try group expense splitting.
  • Test the app on a phone.
  • Add it to the phone home screen.

Admin setup

The first account is not automatically a global admin. To create the admin account:

  1. Sign in once with your own account so Firebase creates your user profile.
  2. Open Firebase Console → Firestore Database → Data.
  3. Create a collection called admins.
  4. Create a document whose document ID is your Firebase Authentication user UID.
  5. Add a Boolean field named enabled with the value true.
  6. Sign out and sign in again.

You can find your UID in Firebase Console → Authentication → Users. Once the admin document exists, Tripwise shows the Admin banner, the Clear all data button and Manage members controls.

Admin data controls

  • The admin can delete any trip and any expense.
  • Clear all data deletes trips, expenses and legacy workspace documents from Firestore. It does not delete Firebase login accounts.
  • Other users can delete only expenses where their Firebase UID is the createdByUid.
  • Other users cannot delete another user's expense because Firestore Rules enforce this even if someone changes the browser code.

Manage users on a trip

  1. Each person must create a Firebase account and sign in once.
  2. Open a trip as the admin.
  3. Click Manage members.
  4. Check the users who should access the trip.
  5. Uncheck a user to remove access. The trip owner cannot be unchecked.
  6. Click Save members.

Members can then see the trip, add their own expenses and use equal splitting. Only the admin can add or remove members.

Offline use and automatic sync

Tripwise uses Firebase Firestore's IndexedDB offline persistence. It does not use localStorage for trip data.

  • Open the app online at least once and sign in.
  • If the network stops, Firestore keeps new trips and expenses in its offline queue.
  • The top status changes to Offline · saved for sync.
  • When the device reconnects, Firestore automatically uploads the queued writes.
  • The status changes back to Online · synced after the server acknowledges the data.

Do not clear the browser's site data while offline if you still have unsynced changes.

Important data model note

Trips are stored in Firestore as trips/{tripId} documents and expenses are stored in trips/{tripId}/expenses/{expenseId}. Each expense includes the Firebase UID of the person who entered it.

If something fails

The login screen says Firebase setup is required

Open firebase-config.js in GitHub and replace every placeholder value with the Web app config from Firebase Console. Commit the change, wait for GitHub Actions to deploy, then hard-refresh the website.

GitHub Actions fails with a Firebase service-account error

Check that:

  • The secret is named exactly FIREBASE_SERVICE_ACCOUNT.
  • The secret contains the entire JSON file.
  • The project ID in the workflow exactly matches Firebase.
  • The service account JSON was not pasted into a normal repository file.

Firestore permission denied

Check that:

  • Email/Password Authentication is enabled.
  • The user is signed in.
  • The Firestore Rules were published.
  • The rules contain request.auth.uid == userId.

The website shows an old version

Open the GitHub Actions tab and check that the latest workflow succeeded. Then hard-refresh the browser. On a phone, close the installed app completely and open it again.
